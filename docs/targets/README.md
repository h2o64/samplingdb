# Targets

## Two splits

`train_samples()` is cheap and deliberately biased, so a sampler may train on it. It covers what
the test split covers and gets the rest wrong:

- on a target with modes, every mode is visited, in proportions far from the true ones;
- on a unimodal posterior or the funnel, the whole support is visited with the wrong shape;
- everywhere, the energy histogram (`-log_prob`) spans the test split's, both tails included.

The default train split, 100 000 samples at seed 0, is published with the reference sets and
downloaded on first use, so every user reads the same array. Any other size or seed is generated
locally and cached, by the recipe its target's `generate_train_samples` docstring states.

On the targets with modes each chain draws its mode with skewed shares, starts from an exact draw
of that mode and takes a short random walk. The posteriors run chains at a ladder of temperatures
either side of the target's. The particle systems run most of their chains hotter than the target
and a tenth or a thin run of colder ones, so the train energies sit mostly above the test ones and
only the colder chains cross them. The glasses do the same with displacements inside 100 basins
made with swap moves on the ternary, the coldest basins taking the most chains.
The peptides place every residue in a backbone basin, alpha-L the most often, and run Langevin
dynamics from there.

```python
import samplingdb

target = samplingdb.build('lj13')
x = target.train_samples()                   # the published split: 100 000 samples, 1000 chains
y = target.train_samples(n=20000, seed=1)    # another split, generated once and cached

# Uncached: the same 1000 chains continued from their last states (their step sizes adapt again
# over the first n_steps moves), then longer chains at a narrower temperature ladder
z = target.generate_train_samples(100000, x0=x[-1000:])
w = target.generate_train_samples(100000, n_steps=5000, temperatures=(0.9, 1.1))
```

`generate_train_samples(n, seed=0, x0=None, ...)` is the recipe itself, uncached. Every target
takes `x0`, whose rows replace the starting points (chain `i` starts from `x0[i % len(x0)]`), and
exposes its own knobs as keyword arguments. A split holds its chains frame by frame, so its last
`n_chains` rows are the last state of every chain, in chain order. The recipe runs on the target's
device: the glasses and the peptides take under a minute on a GPU and many minutes on the CPU, so
move them first with `target.to('cuda')`.

`test_samples()` is the reference a sampler is scored against. It is exact draws where those are
free, and otherwise a reference set generated by this library (see
[Reference sets](../reference-sets.md)), which the first call downloads (see
[Data and cache](../interface.md#data-and-cache)).

Both splits hold 100 000 samples by default and take any `n`. Another train split size is
generated under its own cache entry; a test split returns its first `n` rows, which span every
chain of the run that generated it.

## Truth tiers

`truth_tier` says how the reference set exists.

| Tier | Family | Reference |
| --- | --- | --- |
| 0 | [Synthetic](synthetic.md) | exact draws |
| 1 | [Particle systems](particles.md) | this library's parallel tempering |
| 2 | [Bayesian posteriors](posteriors.md) | this library's Stan runs, and an exact sampler for `brownian` |
| 3 | [Peptides](peptides.md) | this library's replica-exchange molecular dynamics |
| 4 | [Glass formers](glasses.md) | this library's swap Monte Carlo or parallel tempering |

Every target has exactly this one name: it is what `build` takes, what `target.name` returns, and
what the cache and the published reference sets are keyed by. "Download" is the catalog's `data`
flag: building the target needs a fetched dataset or force-field input. The reference sets are
generated by this library and published separately, and `test_samples()` downloads them on first
use.
